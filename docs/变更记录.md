### 修复云端 dtype 报错

- 来源：云端训练实报 `RuntimeError: expected scalar type double but found float`，精确指向 `finetune_facexformer.py` 的朝向目标构造行。
- 文件：`project/train/src_repo/finetune_facexformer.py`
- 变更：原来用 `torch.where(cond, 3.14, torch.where(cond2, 0.8, 0.0))` 构造朝向的欧拉角目标。在 torch 1.11.0+cu113 上，`where` 的「标量 + 张量」混用不会把标量转换成张量的 dtype，会直接报错；全标量的 `torch.where(t == 1, 3.14, 0.0)` 反而正常，所以只有嵌套那一层会炸。改为 `masked_fill`，全程只有张量，不存在标量 dtype 歧义。
- 通用规则：torch 1.11 及更早版本，`where`/算术运算里不要混用 Python 浮点字面量和张量；常量张量一律显式写 `dtype=torch.float32`。
- 验证：云端实跑通过，产出的 `facexformer_finetuned.pt` 为 368,592,591 字节，与参数量 × 4 字节吻合，确认为完整文件。本地 torch 2.6 的 `copy_` 会自动转换 dtype，**无法复现**该报错，因此必须靠云端实跑确认。

### 修复「超时即零产物」

- 来源：平台单次训练上限 12 小时。原实现把 `torch.save` 放在 epoch 循环之后，一旦超时被杀，已完成的 epoch 全部丢失。实际发生过一次：三份数据集同时挂载、训练样本 250230，单 epoch 约 3.8 小时，5 个 epoch 需约 19 小时，第 4 个 epoch 被超时杀掉。
- 文件：`project/train/src_repo/finetune_facexformer.py`
- 文件：`project/train/src_repo/finetune_swinface.py`
- 变更：把 `torch.save` 移进 epoch 循环，每个 epoch 结束保存一次。
- 变更：新增 `--max_samples N`（0 表示全部），用于控制耗时。切片发生在 `random_split` **之前**，否则训练/验证的 8:2 比例会被打乱。
- 变更：`run.sh` 把 `EPOCHS`、`MAX_SAMPLES`、`BATCH_SIZE_*` 提为文件头变量。
- 注意：`run.sh` 有 `set -e` 且两个脚本串行，前一个没跑完后一个不会开始，所以给 SwinFace 也要留出时间预算。

### 消除重复前向

- 文件：`project/ev_sdk/src/face_attr/models/facexformer/network/models/facexformer.py`
- 变更：`FaceXFormer.forward` 新增 `tasks=None` 分支，返回全部 8 个头。原实现要求按 task 分别调用（`task=4` 取 gender/race、`task=2` 取 headpose），但 `forward` 内部是**无条件**把整个 `face_decoder` 算完再按 `tasks` 切片返回值，因此第二次调用等于把解码器完整重算一遍（约 2 倍算力、2 倍显存峰值）。
- 变更：`finetune_facexformer.py::run_epoch` 改为单次前向。`analyzer._run_facexformer` 同步改用该分支，省下的是榜单 20% 权重里的性能分。
- 附带确认：`forward` 的 `labels` 形参在函数体内从未被使用，调用方可以直接传 `None`，据此删掉了 `labels_for_model`。
- 验证：`_verify_forward.py` 用 `torch.equal` 证明 `tasks=None` 与按 task 切片的结果**逐位相等**。原签名保留，向后兼容。

### 多数据集合并训练：来源统计与分层抽样

- 来源：平台提供 V5/V6/V7/V8 多份数据集，需要「多份数据一起训练出一个权重」。原先同时勾选多份后训练超时，且无法判断数据是否被正确合并读取。
- 文件：`project/train/src_repo/dataset.py`
- 问题一：`samples` 是按 XML 路径 `sorted()` 得到的，具有确定顺序。多份数据合并后如果直接切片取前 N 个，拿到的是**路径最靠前的那一份**而非多份的混合，会退化成「只用了其中一个数据集训练」，且不报错、不易察觉。
- 变更：新增 `self.sources`（与 `samples` 平行的来源标记）和 `self.source_stats`；`_source_group()` 以相对根目录的第一级子目录名作为来源标识。
- 变更：新增 `select_subset(max_samples, seed)`，按来源**等量分层抽样**，再做整体打乱；某份样本不足配额时，剩余名额补给仍有富余的那份，尽量抽满。两个 finetune 脚本改用它替代原来的 `samples[:N]` 直接切片。
- 变更：新增 `_log_source_breakdown()`，打印每份数据的 XML 数、目标数以及 `toward`/`gender`/`race` 分布。用途是核对三件事：来源组数是否等于实际勾选的数据集数、抽样后每份是否都被覆盖、各份的标签口径是否一致。
- 注意：来源统计中计数数组的下标是「标签值 + 1」（`-1` 表示缺失），因此下标 0 是缺失而非第一个类别。实现过程中曾把表头写成 `front/back/other/缺失`，与实际下标全部错位，会让口径核对得出反向结论；已改为逐对打印 `名称=数值`。
- 文件：`project/train/src_repo/finetune_facexformer.py`
- 文件：`project/train/src_repo/finetune_swinface.py`
- 变更：新增 `evaluate()` 和 `val_loader`，每个 epoch 打印验证指标。原先 `val_size` 计算出来后就被 `train_set, _` 丢弃，脚本**完全没有验证集**，只能看到训练 loss，无法判断收敛或过拟合。`MAX_VAL_SAMPLES = 2000` 限制评估开销。
- 说明：验证指标按本脚本的训练目标计算，**不等于榜单 ACC**（榜单中判定 `toward` 正确后才继续判定属性，`back`/`other` 判定正确即得分），用途是观察收敛趋势。
- 决策：不采用「分三次任务接力训练」。接力需要依赖 `/project/train/models/` 跨任务保留（尚无证据），且存在灾难性遗忘风险——而每个脚本的验证集都是「当前这一份」，**测不出**对前一份数据的遗忘。另一个原因是从预训练权重出发、`lr=1e-5` 的微调场景下，数据量从 10 万增至 31 万的边际收益很小，不值得用遗忘风险和平台依赖去换。
- 决策：不采用「三份数据各训一个权重再做权重平均」。权重平均会破坏 BatchNorm 统计量，通常比单份训练更差。
- 验证：`_verify_train_cli.py` 新增 `verify_stratified_subset()`，构造 groupA/B/C 为 30/12/6 个样本的悬殊数据集，抽 30 个实测得到 14/10/6——三组全部覆盖、总量精确、`samples` 与 `sources` 长度一致、且不是顺序截断。`_verify_train_cli.py`、`_verify_forward.py`、`_local_smoke.py`、`pytest tests` 全部通过。未在云端执行真实数据训练。

### 修正耗时估算口径

- 来源：核对云端训练日志。
- 变更：此前记录的「0.218 秒/样本」来自 1085 个样本的小数据集实测，固定开销（模型加载、图片索引、预热）被摊成了每样本开销，严重高估。该值外推 25 万样本会得出「单 epoch 需 15.2 小时」，与日志里实际跑完 3 个 epoch 直接矛盾。
- 修正：由「日志显示跑完 3 个 epoch、第 4 个被超时中断」反推，约 13800 秒/epoch ÷ 250230 训练样本 ≈ **0.055 秒/样本**（FaceXFormer 224 输入、batch 16、单卡）。
- 经验：不要用小数据集实测再线性外推估计大数据的单样本耗时；应从大任务日志里「跑完了几个 epoch」反推。

### FaceXFormer 年龄标签调查

- 文件：`project/train/src_repo/finetune_facexformer.py`
- 当前代码：年龄头输出 8 类，临时年龄边界为 `(0, 4, 13, 20, 30, 40, 50, 60, 101)`。
- 已确认：本地 FaceXFormer 实现的 `age_prediction_head` 输出维度是 8；模型结构本身没有保存年龄边界定义。
- 榜单规则：榜单年龄标签是 `0-100` 或 `-1`，但这只能说明标注输出范围，不能直接推出 FaceXFormer 的 8 个训练年龄桶。
- 当前决定：在查到 FaceXFormer 原始训练代码或官方标签定义前，不把临时边界视为最终方案，也不据此宣称训练结果正确。
- 待确认：FaceXFormer 原始数据集、年龄类别到年龄范围的映射，以及榜单连续年龄标签转换到 8 类年龄目标的规则。
- 代码风险：当前微调脚本中的年龄分桶属于待替换的临时实现；云端训练前必须完成来源核对。

### SwinFace 年龄输出核对

- 文件：`project/ev_sdk/src/face_attr/models/swinface/analysis/subnets.py`
- 结论：SwinFace 的 `Age` 输出头维度为 1，是连续数值回归，不使用年龄桶；模型输出没有 `argmax`。
- 训练：`project/train/src_repo/finetune_swinface.py` 使用有效年龄标签的均方误差损失；年龄为 `-1` 的样本不参与年龄损失。
- SDK：`project/ev_sdk/src/face_attr/analyzer.py` 原样读取 `Age` 回归值；`project/ev_sdk/src/model_api.py` 的 `_age_value()` 会四舍五入，并将结果限制到 `0-100`，空值返回 `-1`。
- 与榜单要求的关系：榜单年龄字段要求 `0-100` 或 `-1`，因此 SwinFace 的年龄输出链路与该格式一致，不需要年龄桶转换。
- 注意：模型本身不会根据训练标签是否为 `-1` 自动输出 `-1`；未知年龄只是在训练时忽略，推理时仍会对检测到的人脸给出回归值。

### 年龄模型职责确定

- 文件：`project/train/src_repo/finetune_facexformer.py`
- 决定：最终年龄以 SwinFace 的连续回归结果为准；FaceXFormer 不再训练年龄分支。

- 原因：当前无法从 FaceXFormer 源码确认 8 个年龄类别的真实边界，而 SwinFace 的年龄输出与榜单 `0-100/-1` 格式一致。
