# 极市线上平台依赖安装

本清单适用于当前项目的训练、SDK 测试和检测框诊断。版本以项目 `requirements.txt` 为准，目标环境为 Python 3.7、PyTorch 1.11、torchvision 0.12、CUDA 11.3。

## 1. 先确认实际使用的 Python

在平台终端执行：

```bash
python -c "import sys; print(sys.executable); print(sys.version)"
python -m pip --version
python -c "import torch, torchvision; print('torch:', torch.__version__); print('torchvision:', torchvision.__version__); print('CUDA build:', torch.version.cuda); print('CUDA available:', torch.cuda.is_available())"
```

已提供的平台终端输出使用 `/opt/conda/bin/python`。安装时统一使用 `python -m pip`，保证包安装到该解释器对应的环境。如果训练或测试另用一个 Python，应使用那个解释器安装并验证。

已有兼容的 GPU 版 PyTorch 和 torchvision 时，保留它们，执行下一节补装其余依赖。目标为 GPU 训练和推理时，`CUDA available` 应为 `True`；若为 `False`，先检查任务是否分配 GPU，以及 PyTorch 是否支持 CUDA。

## 2. 训练和 SDK 必需依赖

| pip 包名 | 项目指定版本 | 导入名称 / 用途 |
|---|---|---|
| torch | 1.11.0；CUDA 11.3 构建为 1.11.0+cu113 | `torch`，训练和推理 |
| torchvision | 0.12.0；CUDA 11.3 构建为 0.12.0+cu113 | `torchvision`，头肩检测器、NMS 与图片预处理 |
| timm | 0.6.13 | `timm`，SwinFace 模型层 |
| facenet-pytorch | 2.5.3 | `facenet_pytorch`，兼容旧 MTCNN 检测和旧检测器对照 |
| numpy | 1.21.6 | `numpy`，图片和数组处理 |
| opencv-python | 4.5.5.64 | `cv2`，训练裁剪及 SDK 图片预处理 |
| Pillow | 9.5.0 | `PIL`，SDK 预处理和检测框对照图 |

在已有兼容 PyTorch/torchvision 的平台环境中执行：

```bash
python -m pip install \
  timm==0.6.13 \
  facenet-pytorch==2.5.3 \
  numpy==1.21.6 \
  opencv-python==4.5.5.64 \
  Pillow==9.5.0
```

缺少 GPU 版 PyTorch/torchvision、需要按项目目标新建环境时，再执行：

```bash
python -m pip install torch==1.11.0+cu113 torchvision==0.12.0+cu113 \
  -f https://download.pytorch.org/whl/torch_stable.html
```

项目中的 `facenet_pytorch-2.5.3` wheel 元数据列出了 NumPy、requests、torchvision、Pillow；`timm-0.6.13` 列出了 torch、torchvision、PyYAML 和 huggingface-hub。这些传递依赖由 pip 一并解析安装；在线补装时不要使用 `--no-deps`。

## 3. 项目其余依赖

`requirements.txt` 还声明了以下分析、绘图、工具和测试依赖；它们并非全部都在 SDK 推理路径上使用：

```text

matplotlib==3.5.3

```

需要安装完整项目环境时，将仓库根目录的 `requirements.txt` 上传到 `/project/requirements.txt`，执行：

```bash
python -m pip install -r /project/requirements.txt
```

完整依赖文件中的 torch/torchvision 基础版本分别为 `1.11.0`、`0.12.0`。安装后应再次检查版本和 CUDA 状态。平台自带的评测客户端环境及其依赖由平台维护，本清单描述的是本项目环境。

JupyterLab 仅在需要 Notebook 开发时安装；项目环境脚本使用 `jupyterlab==3.3.*`，训练及 SDK 入口本身不要求它。

## 4. 安装后验证

以下命令验证必需模块和 Pillow 图像扩展能否实际加载，不加载两份属性模型权重：

```bash
python - <<'PY'
import sys
import torch
import torchvision
import numpy
import cv2
from PIL import Image, ImageDraw
from facenet_pytorch import MTCNN
from timm.models.layers import DropPath, to_2tuple, trunc_normal_
print('Python:', sys.executable)

print('torchvision:', torchvision.__version__)
print('CUDA available:', torch.cuda.is_available())
print('必需依赖导入成功')
PY
```

源码上传完成后，再验证 SDK 和训练入口：

```bash
PYTHONPATH=/project/ev_sdk/src:$PYTHONPATH python -c "import ji; from face_attr.analyzer import AttributeAnalyzer; print('SDK 导入成功:', ji.__file__)"
python /project/train/src_repo/finetune_facexformer.py --help

```

最后一条需要先上传检测框诊断脚本。这里的 `PYTHONPATH=...` 只影响该条命令，不会自动修改平台另行启动的测试进程。测试进程也应包含 `/project/ev_sdk/src` 搜索路径。

## 5. 已遇到的错误和安装位置

- `No module named 'timm'`：SwinFace 所需依赖缺失；安装 `timm==0.6.13`。
- `No module named 'facenet_pytorch'`：测试任务 214117 在 `ji.init()` 导入 MTCNN 时退出；安装 `facenet-pytorch==2.5.3`。pip 包名中的连字符与 Python 导入名中的下划线不同。
- `No module named 'cv2'`：安装 `opencv-python==4.5.5.64`。
- `No module named 'PIL'`：安装 `Pillow==9.5.0`；诊断图和 SDK 预处理需要它。
- `No module named 'ji'`：这是源码位置或模块搜索路径问题，安装上述第三方依赖不能代替上传 `/project/ev_sdk/src/ji.py` 和配置搜索路径。

`run.sh` 只会在 timm 导入失败时尝试补装 timm，不会自动安装全部 SDK 依赖。训练成功也不能单独证明 MTCNN 所需依赖已经可用。

安装成功后新建测试任务。若测试使用此前保存的环境或打包镜像，需要让测试环境包含新依赖和新版完整 SDK 源码；是否需要手动保存或重新打包以平台实际操作为准，不假定平台一定有“更新镜像”按钮。

## 6. 平台不能联网时

可将依赖 wheel 上传到例如 `/project/wheelhouse/`，再使用实际运行测试的 Python 离线安装：

```bash
python -m pip install --no-index --find-links=/project/wheelhouse \
  facenet-pytorch==2.5.3 timm==0.6.13
```

这条命令要求依赖已安装，或对应 wheel 也在目录中，包括 requests、PyYAML、huggingface-hub 等传递依赖。当前本地 `wheelhouse/` 有 facenet-pytorch 2.5.3、timm 0.6.13、PyYAML 6.0.1 三个 wheel，不是完整的离线安装包集合；缺什么仍需提前补齐。包含二进制扩展的 wheel 应匹配平台 Linux、Python 3.7 和 CPU 架构，不使用 Windows wheel。
