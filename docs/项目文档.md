# 人脸属性分析项目文档

本项目保留云平台训练工程和模型榜 SDK 工程。两者统一放在本地 `project/` 目录中，便于整体上传；平台端仍使用固定的 `/project/` 根目录。

## 1. 环境要求

| 组件 | 版本 |
|------|------|
| 操作系统 | Ubuntu 18.04 |
| CUDA | 11.3 |
| cuDNN | 8.2 |
| Miniconda | 3 |
| JupyterLab | 3.3 |
| Python | 3.7 |

## 2. 项目目录结构

本地目录与云平台目录的对应关系如下。上传时将 `project/train/` 的内容放到 `/project/train/`，将 `project/ev_sdk/` 的内容放到 `/project/ev_sdk/`，不要形成 `/project/project/`。

```text
人脸识别/
├── project/
│   ├── train/                # 模型开发，对应平台 /project/train/
│   │   ├── src_repo/         # 训练代码
│   │   ├── models/           # 预训练权重和训练输出
│   │   ├── log/              # 训练日志
│   │   └── result-graphs/    # 训练结果图
│   └── ev_sdk/               # 模型榜 SDK，对应平台 /project/ev_sdk/
│       ├── model/            # FaceXFormer 和 SwinFace 权重
│       └── src/              # SDK 入口和模型适配代码
├── env/                      # 环境安装脚本
├── data/                     # 本地数据，不上传
├── docs/                     # 项目文档
├── pyproject.toml
└── requirements.txt
```

## 3. 环境安装

在 Ubuntu 18.04 上执行：

```bash
bash env/install_env.sh
```

脚本会创建 Python 3.7 环境 `face_attr`，安装 PyTorch 1.11 (cu113)、JupyterLab 3.3 和项目依赖。

## 4. 极市平台使用流程

### 4.1 模型训练

将本地 `project/train/` 内容上传到平台 `/project/train/`，然后执行：

```bash
bash /project/train/src_repo/run.sh
```

训练脚本使用以下平台路径：

- 数据集：`/home/data/`
- 模型输出：`/project/train/models/`
- 日志：`/project/train/log/`
- 结果图：`/project/train/result-graphs/`

### 4.2 模型榜 SDK 测试

将本地 `project/ev_sdk/` 内容上传到平台 `/project/ev_sdk/`。SDK 所需源码已经位于 `project/ev_sdk/src/`，两个权重位于 `project/ev_sdk/model/`，均需保留目录层级：

```text
project/ev_sdk/model/facexformer/model.pt
project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

平台端对应路径为：

```text
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

平台会调用 `src/ji.py` 的 `init()` 和 `process_image()`。后者必须返回包含 `algorithm_data` 和 `model_data.objects` 的 JSON 字符串。

## 5. 训练代码说明

训练入口为 `project/train/src_repo/run.sh`，它按顺序调用两个微调脚本：

- `finetune_facexformer.py`：微调 FaceXFormer 的 gender / race / headpose 三个头
- `finetune_swinface.py`：微调 SwinFace 的 age / glasses / hat / whiskers / emotion

数据集加载逻辑在 `project/train/src_repo/dataset.py`。数据集使用 VOC XML 标注，平台数据目录为 `/home/data/`；没有预先划分的 `train/val` 目录时，代码会按固定种子划分训练集和验证集。

**多个数据集同时勾选**时，`/home/data/` 下多份标注会被合并读取，最终训练出**一个**权重。解析阶段会按数据来源打印分布，用于核对每份数据是否都被读到、抽样后是否都被覆盖、各份的标签口径是否一致。由于总目标数会涨到 30 万以上，必须用 `--max_samples` 控制规模，否则 12 小时上限会被触发。

`--max_samples` 采用**按来源等量分层抽样**：先给每份数据分配相同配额，样本不足的用剩余名额补给还有富余的那份，最后整体打乱。不能改成直接取前 N 个样本——`samples` 是按 XML 路径排序的，那样会退化成「只用了路径最靠前的其中一个数据集」。

两个脚本都在**每个 epoch 结束保存一次**权重，输出到 `/project/train/models/`。这样即使被平台 12 小时上限杀掉，已完成的 epoch 也不会丢失。同时每个 epoch 会打印验证指标（FaceXFormer：`toward/gender/race` 准确率；SwinFace：`age_mae` 和各属性准确率），用于观察收敛与过拟合。注意这些指标按本脚本的训练目标计算，**不等于榜单 ACC**。

单 epoch 冒烟测试：

```bash
cd /project/train/src_repo
python finetune_facexformer.py \
  --data_dir /home/data \
  --epochs 1 \
  --batch_size 8 \
  --max_samples 200 \
  --num_workers 0 \
  --device cuda
```

`--max_samples 200 --num_workers 0` 可以在几分钟内跑完，用于验证数据路径、XML 解析、前向、验证评估和权重保存。正式训练时 `EPOCHS`、`MAX_SAMPLES`、`BATCH_SIZE_*` 在 `run.sh` 开头作为变量统一配置。参考量级：FaceXFormer 224 输入、batch 16、单卡约 0.055 秒/样本。

## 6. 重要说明

微调脚本输出的 `facexformer_finetuned.pt`、`swinface_finetuned.pt` 是临时权重；SDK 默认读取 `/project/ev_sdk/model/` 下的权重。新训练的 FaceXFormer checkpoint 会写入 `gender_classes=["female", "male"]`，新版 `analyzer.py` 加载后自动按 0=女/1=男解码；复制为 SDK 的 `model.pt` 后元数据仍会保留。没有该字段的旧原始权重继续按 0=男/1=女解码。若使用 2026-10-03 修正前产出的旧微调权重，需在 SDK 进程环境中显式设置 `FACEXFORMER_GENDER_ORDER=female,male`；它会覆盖权重元数据，切回原始权重时应移除此设置。训练工程和 SDK 工程可以分别上传，也可以从本地 `project/` 目录中统一取用。

`run.sh` 会在训练前检查 SwinFace 的 `timm.models.layers` 依赖，缺失时使用当前训练解释器安装 `timm==0.6.13`；随后通过两个训练脚本的 `--help` 检查完整源码导入。安装或导入失败就立即退出，避免 FaceXFormer 训练数小时后才发现 SwinFace 无法启动。自动安装需要平台能访问 pip 源；无法联网时，先在实际训练环境中离线安装依赖。
