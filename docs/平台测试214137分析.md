## 2. 预处理差异已确认，精度影响待对照

FaceXFormer 训练端使用 OpenCV 双线性缩放到 224×224；SDK 使用 PIL 双三次缩放到相同尺寸。RGB 转换及 ImageNet 归一化一致。SwinFace 的训练和 SDK 都使用 OpenCV 双线性缩放到 112×112，未发现相同差异。

这能说明存在输入差异，不能说明改成双线性一定提升榜单分数。先在相同权重、相同裁剪框上比较两种方式，再决定是否更改 SDK。

## 3. 少数类别解码未发现截断

已检查眼镜三分类、口罩、表情、胡须的训练标签与 SDK 解码。当前 SDK 能输出墨镜 `2`，没有发现强制二分类或将 other 解码成 -1 的问题，相关 5 项针对性检查通过。

可解析的本次日志子集含 3118 个预测正面目标：眼镜没有出现 `2`；表情几乎都是 `2`；胡须仅 1 个 `1`。该分布值得检查，但没有同一批目标的真实类别分布，不能计算墨镜/胡须正类召回率。日志部分行存在编码或格式损坏，分布只代表可解析子集，不能据此判定 SDK 报错。

训练日志显示墨镜、帽子、胡须正类较少。例如胡须验证集只有 3 个正类、293 个负类，全预测负类也能达到 98.99%。因此暂不依据整体准确率调整类别权重或重新训练；应先取得本轮 `*.validation.json` 中的混淆矩阵和各类召回率。

## 4. 逐目标推理会增加耗时

SDK 对每个头肩分别运行 FaceXFormer，对预测正面目标再分别运行 SwinFace。日志可解析子集中，头肩数量约从每图 1.32 增至 1.72，正面目标约从每图 0.45 增至 0.52。

按相同目标数量分组后，没有发现单图平均耗时上升。例如只有一个头肩且没有正面目标的图片约从 74 ms 降至 72 ms；一个正面目标约从 135 ms 降至 132 ms。更多目标导致更多串行调用，是 FPS 下降的一个合理解释，但这不是受控性能实验。

此处为214137时的检查结论；后续已实施同帧批量推理，214144实测见文末。

`背面分类错误明细` 在日志最多打印50个匹配后的SDK背面分类错误，包含图片路径、两套框坐标、匹配IoU、两种裁剪的SDK类别及分数。完整结果仍保存在JSON；超过50个时可从汇总看总数，不能将明细数量当总错误数。

`softmax` 是front/back/other三项模型分数，并非经校准的真实正确概率。`back_minus_other_logit` 为back原始分数减other原始分数；小于0表示other分数更高，只能用于分析两类差距，不能单凭这个值直接定SDK阈值。即使该差值为正，front仍可能有最高分，因此最终类别仍以SDK预测为准。

可选分数采集仅在诊断中观察已有toward_classifier前向输出，不额外跑模型、不替换输出；每次采集后移除观察钩子，异常时也恢复原缩放函数。正式analyzer.py、模型和协议未修改。20项小范围检查及Python3.7语法检查通过，线上实际结果待日志确认。无需重新训练，完成后提供任务日志即可。
