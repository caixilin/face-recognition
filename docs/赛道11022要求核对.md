# 极市 11022 人脸属性分析赛道核对

核对日期：2026-10-03。依据：[官方赛道说明](https://www.cvmart.net/topList/11022?tab=RankDescription)，第 5 节数据标签、第 6.1 节模型榜及 JSON 字段说明。

## 2026-10-05 补充核对：连续帧与跨帧复用

214146试验未显示收益，已按用户要求将ji.py中的连续帧复用默认关闭。下文描述保留的可选缓存实现；当前默认仍每帧运行检测和属性模型。

本次已通过浏览器读取赛道说明正文。第3节将输入描述为彩色非实时连续帧；第5.1节明确测试集由连续帧图片构成，同一文件夹中为同一视角、同一人的多张图片。这项信息应纳入推理效率设计。214145版本每次独立检测和属性推理；用户随后要求尝试连续帧复用，已在model_api.py及ji.py加入实验性短期属性缓存，当前坐标仍由每帧检测产生。

第6.1节当前模型榜规则仍为定制ACC占80%、FPS相对30FPS占20%；预测朝向错误直接判错，front判对后检查属性，back/other判对后直接判正确。框定位和朝向仍要保持有效，非正面目标无需运行完整属性模型；当前SwinFace只对预测front执行，已经符合这项门控。

可考虑给同一真实目标建立短期跨帧关联，复用相对稳定的性别、年龄、人种预测，减少重复属性模型计算；表情、朝向、口罩及配饰变化需要及时更新。不能简单把上一帧整个JSON或框复制到下一帧。多个目标、新进场人员、遮挡后重现、场景切换和失去匹配都必须重新识别/失效缓存。当前target_id按每帧置信度顺序生成，不能作为跨帧身份缓存键；字段说明要求同一人的ID唯一，关联设计应同时核对这个要求。

**官方确认的内容与待核实条件需要分开：**同文件夹属于连续帧，不等于模型榜测试程序必然按文件名/时间顺序调用；第6.1节只说图片逐次送入process_image，没有展示文件夹切换/帧号元数据。新ji.py支持调用方明确提供sequence_id时清空缓存，但尚不清楚线上是否传此信息。handle保存上一帧缓存，通过双向无歧义框匹配及严格图像相似度检查，最多连续复用两帧后强制刷新；尺寸/场景变化、目标消失等使缓存失效。内部匹配不用每帧target_id当身份键；此功能不改变现有输出ID，也不是完整跟踪实现。细微表情/朝向变化或外观近似的不同人仍有误复用风险，线上精度和关联正确性待验证，不能声称已完全满足所有序列/身份要求。

页面第6.2节是另一个算法榜，采用MOTA/MOTP、100FPS基准及process_video；C++说明中的args切换和最后一帧计分也位于这部分。不能据此声称当前第6.1节模型榜只评最后一帧，或可以省略中间帧结果。每次process_image仍返回当前输入的完整协议结果。

当前试验在相同模型榜流程中比较FPS、复用率和准确率，步骤及关闭方法见 [线上平台上传清单](线上平台上传清单.md)。是否允许某一种具体的跳帧/缓存策略，页面没有明确展开说明，不能把数据说明当作其具体策略的官方许可或速度保证。每帧检测及完整协议返回仍保留。

当前结论：头肩检测、眼镜三分类、口罩及朝向分类已实现训练和 SDK 接入，任务182201三套模型已用于后续平台测试；连续帧缓存属于新试验，效果待线上确认。保留此前已验证的输出协议、告警逻辑和旧属性权重兼容。未挂载头肩新权重时仍使用原 MTCNN，不能把这种兼容模式称为已完成头肩检测。训练接入的历史步骤见 [头肩检测升级与线上重训](头肩检测升级与线上重训.md)。

## 1. 四项验证限制如何理解

| 原有限制 | 与官方要求的关系 | 当前处理 |
| --- | --- | --- |
| 验证最多 2,000 个目标，只统计有标签的样本 | 2,000 是本地开销限制，官方未规定此上限。缺失标签可在训练诊断中跳过，但官方没有公开完整的测试计分分母。 | 两个训练脚本增加 `--max_val_samples`，0 表示完整验证部分；记录实际评估数、每项有效数及忽略数。仍是裁剪图诊断。 |
| 眼镜把标签 1、2 合并 | **无法作为官方三分类能力的证明**。官方区分普通眼镜与墨镜。 | 新训练模型使用三分类，SDK 支持输出 2，主指标为 `glasses_3class_acc`。原始模型基准仍只有 0/1 输出，墨镜标签计错；`glasses_binary_acc` 另列作为辅助。 |
| 帽子、胡须无类别分布 | 官方未要求上传这些统计，但只有整体准确率无法排除类别不平衡。 | JSON 报告记录各类样本量、正确数、各类召回率、混淆矩阵及有样本类别的平均召回率。某类没有样本时为 null，不能宣称该类达标。 |
| 没有原始模型基准 | 官方未要求提供原始模型对照；“微调优于原始”却需要可比证据。 | 默认在更新参数前评估初始 checkpoint，再评估每轮微调，使用同一验证加载器。`--skip_baseline` 可跳过，但报告明确标为无基准。 |

原始基准指 `--checkpoint` 实际指定的初始文件；如果指定的已经是微调模型，这不是预训练原始模型基准。FaceXFormer 对照按 checkpoint 的 `gender_classes` 解码；无元数据按原始模型 male/female 顺序。旧微调权重没有元数据时不能冒充原始权重作对照。

## 2. 官方模型榜与本地指标的差别

官方第 6.1 节的精度使用定制 ACC：朝向错误直接计错；正面朝向正确后再判断属性；背面与其他朝向识别正确直接计正确。精度占 80%，性能占 20%，性能以 FPS 相对 30 FPS 衡量。

本地两个训练脚本使用已知标注裁剪图，没有经历整图检测、框匹配、朝向门控和端到端计时。因此，所有单项准确率、年龄 MAE 及平均召回率都只是诊断，不是最终 ACC 或总分，也不能将它们简单平均后当作榜单成绩。

官方网页没有公开完整的框匹配算法、IoU 阈值、属性子权重、年龄容差、缺失标签计分分母或性能是否封顶。此前测试日志中的具体配置只能说明那次测试；不能据此声称已经复现全部官方评分。最终以当前平台模型测试的实际评估程序和结果为准。

网页第 6.2 节另有跟踪指标、`process_video` 和结果 TXT；其中部分标题混用了“模型榜”。当前项目与用户测试日志使用第 6.1 节 `process_image` 接口，不能套用跟踪部分“不计性别年龄”的说明。

## 3. SDK 和模型能力核对

| 项目 | 官方任务要求 | 当前实现及结论 |
| --- | --- | --- |
| 输入与入口 | BGR 图片，`/project/ev_sdk/src/ji.py` 中的 `init` / `process_image`，返回 JSON 字符串 | 已有对应入口；模型真实加载仍依赖线上安装和挂载路径。 |
| 检测区域 | `head` 指头肩；数据 A 有人和头肩框，数据 B 是头肩小图 | 已新增按原图 person/head VOC 框训练的检测器，挂载新权重后直接输出其框。缺少新权重时保留原 MTCNN 和框推算以兼容已验证程序，此模式不满足头肩检测效果目标。 |
| 朝向 | front/back/other，按双眼可见情况与侧面情形标注 | 新权重用 toward 三分类损失训练，SDK 使用同一分类头。旧权重保留角度阈值近似；30°/90° 不是官方定义。 |
| 眼镜 | 0 无、1 普通、2 墨镜，-1 不可判断 | 新模型新增第三类参数，训练保留标签 2，SDK 按 checkpoint 解码三类；旧二分类权重继续兼容。 |
| 口罩 | 0 无、1 有，-1 不可判断 | 新模型增加 Mask 分类头和损失，SDK 输出预测值；旧权重没有该头时仍是 -1。 |
| 性别、人种 | 性别 0 女 / 1 男；人种 0–3 | 新微调性别顺序已写入 checkpoint；SDK 有范围检查。效果需真实验证。 |
| 表情 | emotion：0 皱眉 / 1 笑 / 2 平静，-1 其他 | 沿用已有 SwinFace 映射和已验证 expression 兼容输出；网页两字段语义不同的歧义保留在验收事项中，本次不修改协议。 |
| 年龄、帽子、胡须 | age 0–100，帽子/胡须 0/1，-1 不可判断 | 当前有对应预测；胡须使用 Mustache 输出，原始模型对其他胡须类型的覆盖没有得到证明，微调效果须按平台 whiskers 标签验证。年龄 MAE 不等于平台年龄命中率。 |
| 告警 | 示例正面告警、背面不告警，检测结果保留在 model_data | 按用户要求保留此前线上通过的所有 head 进入 target_info 的逻辑。与网页示例的差异仍需业务验收确认，本次不根据示例擅自调整。 |
| ID | 同一人的标识唯一 | 当前按每帧检测顺序编号，没有跨帧身份关联；如果部署要求连续帧稳定 ID，需增加跟踪。 |

官方 SDK 示例与字段表也存在差异：年龄示例为字符串、表格为 Int32；部分 `toward` 示例带尾部空格；`expression` 示例与数值 emotion 并非同一套标签。当前保留可运行的 `toward`、数值字符串和 emotion，不能擅自复制示例笔误或据此保证所有字段歧义已消除。业务告警、ID 和字段类型需要以实际验收接口补充确认。

## 4. 如何使用修正后的验证

上传完整 `/project/train/src_repo/`，包括新增的 `validation_metrics.py`。在 `run.sh` 中将 `MAX_VAL_SAMPLES=0` 可评估所选训练子集的全部验证目标；这仍不是平台隐藏测试集。初始基准默认执行，会增加训练耗时。

每个模型的验证详情保存在：

```text
/project/train/models/facexformer_finetuned.pt.validation.json
/project/train/models/swinface_finetuned.pt.validation.json
/project/train/models/headshoulder_finetuned.pt.validation.json
```

报告含初始权重指标、各轮指标、验证目标数和每项类别统计。全缺失标签的指标为 null；没有样本的类别召回率也为 null。不要把缺失当作正确或把 null 当作 0。

划分仍是固定种子 42 的目标级随机 80/20 划分；同一图片的目标及连续帧可能同时出现在训练和验证中。对照只支持该划分下的裁剪图指标比较，不能证明跨摄像头泛化；正式评估应按图片/视频序列或摄像头分组留出数据，并运行完整 SDK。
