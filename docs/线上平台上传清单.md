# 极市线上平台上传清单

当前方案 B 会分别微调 SDK 使用的 FaceXFormer 和 SwinFace。训练阶段使用原始权重备份作为输入，将结果保存到训练产物目录；完成加载、推理和效果确认后，才决定是否替换 SDK 权重。因此训练前必须同时准备训练代码、SDK 源码和两个初始权重及其备份。

## 一、环境

平台环境与项目目标一致：

```text
Python 3.7
PyTorch 1.11
CUDA 11.3
数据集目录 /home/data/
```

## 二、上传目录

将本地 `project/` 下的 `train/` 和 `ev_sdk/` 上传到平台，不能形成额外的 `/project/project/` 层级。

训练代码至少应存在：

```text
/project/train/src_repo/dataset.py
/project/train/src_repo/finetune_facexformer.py
/project/train/src_repo/finetune_swinface.py

```

FaceXFormer 和 SwinFace 的源码、权重必须存在：

```text
/project/ev_sdk/src/face_attr/models/facexformer/
/project/ev_sdk/src/face_attr/models/swinface/

/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt

/project/ev_sdk/model/swinface/checkpoint_original.pt
```

训练代码只有 `dataset.py`、`finetune_facexformer.py`、`finetune_swinface.py`、`run.sh` 四个文件。早期的 `train.py`（玩具 CNN，方案 A）和与之同名的 `model.py` 已经删除，不要再上传。

权重不提交到 GitHub，但云平台训练前必须准备好两个当前 SDK 权重及其备份。微调脚本默认读取备份，不会覆盖 `/project/ev_sdk/model/` 下的原始文件。

## 三、发起训练

平台训练命令填写：

```bash
bash /project/train/src_repo/run.sh
```

新版入口会在训练前检查 SwinFace 的 `timm.models.layers`，检查不通过时安装项目指定的 `timm==0.6.13`，并验证两个训练脚本都能导入源码。安装或导入失败会立即终止任务，不再等 FaceXFormer 跑完才报缺包。若平台不能访问 pip 源，需提前在实际训练环境中离线安装依赖。

重新完整训练前，上传修正后的 `run.sh`、`finetune_facexformer.py`、`finetune_swinface.py`。SDK 测试前还需更新 `src/model_api.py` 和 `src/face_attr/analyzer.py`。训练任务仍依次从原始备份微调两个模型，输出文件同名覆盖；需要保留上次产物时先下载备份。

模型保存路径可以填写：

```text
/project/train/models
```

数据集选择平台提供的 V5、V6、V7 或 V8，脚本统一从 `/home/data/` 读取，不硬编码版本号。

同时勾选多份数据集时，它们会在 `/home/data/` 下被合并成一份被一起读到，最终训练出**一个**权重。但因为总目标数会涨到 30 万以上，必须用 `--max_samples` 控制规模（见下节）。**不要**改成分三次任务各训一个权重再合并权重文件，权重平均会破坏 BatchNorm 统计量，通常比单份训练更差。

`run.sh` 会依次执行（`EPOCHS`、`MAX_SAMPLES`、`BATCH_SIZE_*` 是脚本开头的变量）：

```bash
python /project/train/src_repo/finetune_facexformer.py \
  --data_dir /home/data \
  --epochs "$EPOCHS" \
  --batch_size "$BATCH_SIZE_FACEXFORMER" \
  --max_samples "$MAX_SAMPLES" \
  --lr 1e-5 \
  --num_workers 4 \
  --device cuda \
  --checkpoint /project/ev_sdk/model/facexformer/model_original.pt \
  --output /project/train/models/facexformer_finetuned.pt

python /project/train/src_repo/finetune_swinface.py \
  --data_dir /home/data \
  --epochs "$EPOCHS" \
  --batch_size "$BATCH_SIZE_SWINFACE" \
  --max_samples "$MAX_SAMPLES" \
  --lr 1e-5 \
  --num_workers 4 \
  --device cuda \
  --checkpoint /project/ev_sdk/model/swinface/checkpoint_original.pt \
  --output /project/train/models/swinface_finetuned.pt
```

训练成功时应分别看到：

```text
saved /project/train/models/facexformer_finetuned.pt
saved /project/train/models/swinface_finetuned.pt
```

每个 epoch 都会打印训练 loss 和验证指标，两者都应为有限数字，不能出现 `nan` 或 `inf`：

```text
FaceXFormer epoch 1/5 loss=0.63930 toward_acc=0.9123 gender_acc=0.9871 race_acc=0.8455
SwinFace epoch 1/5 loss=1.20344 age_mae=6.812 glasses_acc=0.9730 hat_acc=0.9988 whiskers_acc=0.9971 emotion_acc=0.8904
```

注意这些验证指标是按本脚本训练目标计算的，**不等于榜单 ACC**（榜单里判定 `toward` 正确后才继续判定属性，`back`/`other` 判定正确即得分）。它的用途是观察收敛与过拟合。

### 确认数据挂载是否符合预期

解析标注阶段会按数据来源打印分布，训练前务必先读这一段：

```text
数据集来源分布: 3 组，129975 张不同图片
  V5: XML 43325 个，目标 104262 个 | toward 缺失=0/front=80000/back=12000/other=12262 | gender 缺失=0/0=52131/1=52131 | race 缺失=0/0=.../1=.../2=.../3=...
  V6: ...
  V7: ...
--max_samples 生效: 312787 -> 100000 个样本（按 3 份数据等量分层抽样，已打乱）
  抽样后各来源: V5 33334 个，V6 33333 个，V7 33333 个
```

需要核对三件事：

1. **来源组数等于实际勾选的数据集数**。如果只显示 1 组，说明多份数据落在同一目录层级，分层会退化为整体随机抽样（不会报错，但要知道）。
2. **抽样后每一份都有样本**。脚本按来源等量抽样，不会让样本数少的那份被淹没；某份样本不足配额时，剩余名额会补给还有富余的那份。
3. **各份的属性分布口径一致**。若某一份的 `gender 0=`/`1=` 比例与其他份明显相反，或 `race` 只出现部分类别，说明标签定义不同，**不要合并训练**，否则模型会学到自相矛盾的标签。

### 12 小时上限与 `MAX_SAMPLES` 的定法

平台单次训练最长 12 小时，超时会直接杀掉任务。已知坑：

- 两个脚本**串行**执行且 `run.sh` 有 `set -e`，所以前一个没跑完，后一个根本不会开始。给 SwinFace 也要留时间。
- 之前有一次 12 小时超时，是因为同时勾选了三份数据集（`有效目标 312787`、训练样本 250230），单 epoch 约 3.8 小时，5 个 epoch 要 19 小时，第 4 个 epoch 就被砍掉了。
- 两个脚本现在**每个 epoch 结束都保存一次**权重。这样即使被超时杀掉，已完成的 epoch 也不会丢；但仍然**不能**指望靠它跑完 5 个 epoch。`run.sh` 原来是循环结束后才存一次，被砍掉就是零产物。

定 `MAX_SAMPLES` 的方法：在平台终端跑一次单 epoch 并计时，算出每秒能处理的样本数，再让 `MAX_SAMPLES × 0.8 × EPOCHS ÷ 每秒样本数` 落在 12 小时以内并留出余量。

参考量级（单卡、FaceXFormer 224 输入、batch 16）：约 **0.055 秒/样本**。按此估算 `MAX_SAMPLES=100000` 时，FaceXFormer 训练 8 万样本 × 5 epoch ≈ 6.1 小时，SwinFace 输入 112 更省、约 2 小时，合计约 8 小时。

这个数字来自「日志显示跑完了 3 个 epoch」的反推，不要用小数据集外推——固定开销（模型加载、图片索引、预热）会被误当成每样本开销，导致严重高估。

## 四、建议的冒烟测试

正式训练前，可以在平台终端分别执行一次单 epoch 测试。用 `--max_samples` 把规模压到很小、`--num_workers 0` 排除多进程干扰，可以在几分钟内验证数据路径、XML 解析、模型前向、验证评估和权重保存。

```bash
cd /project/train/src_repo
python finetune_facexformer.py \
  --data_dir /home/data \
  --epochs 1 \
  --batch_size 4 \
  --max_samples 200 \
  --num_workers 0 \
  --device cuda
```

通过后执行：

```bash
python finetune_swinface.py \
  --data_dir /home/data \
  --epochs 1 \
  --batch_size 4 \
  --max_samples 200 \
  --num_workers 0 \
  --device cuda
```

两个冒烟测试都通过后，再执行正式的 `run.sh`。SwinFace 的 BatchNorm 不接受 batch size=1，冒烟测试不要写 `--batch_size 1`。

## 五、训练后 SDK 测试

训练完成后，临时微调权重位于：

```text
/project/train/models/facexformer_finetuned.pt
/project/train/models/swinface_finetuned.pt
```

**优先使用平台的训练产物挂载功能。** 发起模型测试时，在「模型列表」中选择同一训练任务的 `facexformer_finetuned.pt` 和 `swinface_finetuned.pt`。平台界面说明这些文件会挂载到与保存路径一致的位置，即上述 `/project/train/models/` 路径。训练任务 182184 的日志确认两个文件均已保存并被平台收集；开发环境中看不到文件，不代表训练产物不存在。

新版 `ji.py` 会分别优先加载这两个挂载的微调文件，并在日志中输出 `SDK 加载权重: ...`。使用前需将新版 `ji.py` 上传到 `/project/ev_sdk/src/ji.py`，并确保它进入实际测试环境或镜像。只选择一个微调文件时，另一个模型会回退到 SDK 权重；测试两套微调模型时应同时选择两个文件。

未找到挂载的微调文件时，SDK 回退到以下两个文件：

```text
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

如果采用手动部署方式，先从平台模型产物列表下载两个微调文件并上传到开发环境的 `/project/train/models/`。确认训练产物可用且 `model_original.pt`、`checkpoint_original.pt` 原始备份已保留后，在平台终端执行：

```bash
cp /project/train/models/facexformer_finetuned.pt /project/ev_sdk/model/facexformer/model.pt
cp /project/train/models/swinface_finetuned.pt /project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

这些命令会覆盖当前 SDK 权重。复制完成后再发起测试；如果测试使用打包镜像，还需更新镜像，使其包含替换后的文件。旧版 `ji.py` 只读取 SDK 权重路径，不能直接使用平台挂载到 `train/models/` 的微调产物；新版支持上述挂载方式。

**权重替换与 `ModuleNotFoundError: No module named 'ji'` 是两个独立问题。** 后者发生在测试进程执行 `import ji` 时，尚未进入模型权重加载阶段；复制权重不能解决这个导入错误。需要确认测试环境中存在 `/project/ev_sdk/src/ji.py`，并将 `/project/ev_sdk/src` 加入实际测试进程的 Python 模块搜索路径。

测试任务 214117 已能调用 `ji.init()`，但在 `from facenet_pytorch import MTCNN` 处因缺少依赖退出。这仍发生在模型权重加载前，与模型选择无关。在实际测试使用的 Python 环境中安装并验证：

```bash
python -m pip install facenet-pytorch==2.5.3 timm==0.6.13
python -c "from facenet_pytorch import MTCNN; from timm.models.layers import DropPath, to_2tuple, trunc_normal_; import ji; print(ji.__file__)"
```

如测试使用打包镜像，需在安装成功后更新镜像；开发终端安装成功并不能单独证明已有测试镜像包含该依赖。

新版 FaceXFormer 微调权重内含 `gender_classes=["female", "male"]`，新版 SDK 自动读取该顺序，不需要再手动改性别解码代码。原始权重没有该字段，默认仍按 0=男/1=女解码。旧版微调产物没有类别元数据，使用它时在 SDK 进程环境设置 `FACEXFORMER_GENDER_ORDER=female,male`；该设置会覆盖权重元数据，换回原始权重时移除。

当前模型职责为：

- FaceXFormer：朝向、性别、种族；
- SwinFace：年龄、表情、眼镜、帽子、胡须；
- 年龄最终以 SwinFace 的连续回归结果为准；
- `emotion=-1` 不参与 SwinFace 表情损失。
