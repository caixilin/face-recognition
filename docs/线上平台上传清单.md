# 极市线上平台上传清单

这份文档用于把本项目上传到线上训练平台。项目分为两个部分：

- **训练工程**：用于训练模型，上传到 `/project/train/`
- **模型榜 SDK**：用于模型测试，上传到 `/project/ev_sdk/`

如果当前只进行训练，先完成第一部分即可，不需要先上传 SDK。

## 上传方式总览

本地项目已经整理在 `project/` 文件夹中。上传到线上平台时，直接把本地的 **`project` 文件夹整体拖入平台的文件上传区域** 即可，不需要逐个选择 `train/` 或 `ev_sdk/` 内的文件。

拖入后应当得到以下线上目录：

```text
/project/train/
/project/ev_sdk/
```

不要把项目根目录（包含 `README.md`、`docs/`、`tests/` 等文件）整体拖入平台，也不要再次套一层 `project/`。如果平台已经存在 `/project/` 目录，应将本地 `project/` 文件夹中的 `train/` 和 `ev_sdk/` 内容上传到对应位置，避免出现：

```text
/project/project/train/
/project/project/ev_sdk/
```

GitHub 仓库和本地项目均不上传模型权重文件。FaceXFormer 和 SwinFace 权重体积较大，已由 `.gitignore` 排除；如云平台的 SDK 测试需要权重，应在云平台上按照后文的目录结构另行上传或准备权重。

## 一、训练工程上传

### 1. 上传训练工程

直接拖入：

```text
project/
└── train/
```

确认平台中存在：

| 本地文件 | 上传到线上 |
|---|---|
| `project/train/src_repo/dataset.py` | `/project/train/src_repo/dataset.py` |
| `project/train/src_repo/model.py` | `/project/train/src_repo/model.py` |
| `project/train/src_repo/train.py` | `/project/train/src_repo/train.py` |
| `project/train/src_repo/run.sh` | `/project/train/src_repo/run.sh` |

训练阶段实际运行所需的代码文件只有这 4 个：

```text
project/train/src_repo/
├── dataset.py
├── model.py
├── train.py
└── run.sh
```

### 2. 线上训练目录

根据你提供的线上平台截图，目前实际目录是：

```text
/project/train/
├── src_repo/
│   ├── dataset.py
│   ├── model.py
│   ├── train.py
│   └── run.sh
├── log/
├── models/
│   └── best_model.pth     # 训练成功后生成
└── result-graphs/
```

其中：

- `/project/train/src_repo/`：放训练代码。
- `/project/train/log/`：训练日志目录，截图中为空。
- `/project/train/models/`：训练结果会写入这里，成功后通常生成 `best_model.pth`。
- `/project/train/result-graphs/`：训练结果图目录，可以为空。

`run.sh` 会自动创建日志、模型和结果图目录。训练工程不需要 FaceXFormer 或 SwinFace 权重。

### 3. 需要上传和排除的文件

以下文件不是训练必须文件：

```text
__pycache__/
*.pyc
.git/
.gitignore
README.md
models/README.md
本地 data/
```

不要上传任何 `.pt`、`.pth`、`.ckpt` 或 `.onnx` 权重文件到 GitHub。训练工程不依赖 FaceXFormer 和 SwinFace 权重；训练完成后生成的 `best_model.pth` 也只保留在云平台训练目录中，不提交回 GitHub。

尤其不要把本地项目根目录整体直接上传到 `/project/train/`，否则容易形成错误的多层目录。直接把本地 `project/` 文件夹拖入平台后，训练代码应映射为：

```text
/project/train/src_repo/train.py
```

### 4. 发起训练时的填写方式

在平台“发起训练”页面填写：

```text
执行命令：
bash /project/train/src_repo/run.sh

模型保存路径：
/project/train/models
```

预加载模型先不要勾选。数据集选择平台提供的对应版本，例如：

训练数据由平台挂载到 `/home/data/`，不需要把本地数据上传到项目目录。

### 5. 训练开始后的正常现象

训练日志应当出现类似内容：

```text
使用设备: cuda
数据集目录: /home/data
训练样本数: ...，验证样本数: ...
Epoch [1/50] train_loss=... val_loss=...
```

`train_loss` 和 `val_loss` 必须是数字，不能是：

```text
nan
```

训练成功后，模型通常保存为：

```text
/project/train/models/best_model.pth
```

### 6. 快速冒烟测试

不建议每次排查都直接跑 50 个 epoch。当前 `train.py` 支持限制样本数和 DataLoader worker 数，可以先用少量样本测试路径、XML 解析、模型前向和保存流程。

平台终端中执行：

```bash
cd /project/train/src_repo
python train.py \
  --data_dir /home/data \
  --epochs 1 \
  --batch_size 4 \
  --max_samples 32 \
  --num_workers 0 \
  --device cuda
```

快速测试正常时应看到：

```text
使用设备: cuda
训练样本数: ...，验证样本数: ...
Epoch [1/1] train_loss=... val_loss=...
保存最优模型: /project/train/models/best_model.pth
训练完成！
```

确认测试通过后，再使用平台发起正式训练：

```bash
bash /project/train/src_repo/run.sh
```

## 二、模型榜 SDK 上传

模型榜测试与训练是两个独立工程。只有准备模型榜测试时，才需要上传这一部分。

### 1. 上传 SDK 工程

如果需要进行模型榜测试，直接拖入本地的：

```text
project/
└── ev_sdk/
```

确认平台中存在：

| 本地文件或目录 | 上传到线上 |
|---|---|
| `project/ev_sdk/src/ji.py` | `/project/ev_sdk/src/ji.py` |
| `project/ev_sdk/src/model_api.py` | `/project/ev_sdk/src/model_api.py` |
| `project/ev_sdk/src/face_attr/` | `/project/ev_sdk/src/face_attr/` |
| 云平台另行准备的 FaceXFormer 权重 | `/project/ev_sdk/model/facexformer/model.pt` |
| 云平台另行准备的 SwinFace 权重 | `/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt` |

### 2. 线上 SDK 目录

```text
/project/ev_sdk/
├── src/
│   ├── ji.py
│   ├── model_api.py
│   └── face_attr/
│       ├── __init__.py
│       ├── analyzer.py
│       ├── detector.py
│       ├── main.py
│       └── models/
│           ├── facexformer/
│           └── swinface/
└── model/
    ├── facexformer/
    │   └── model.pt
    └── swinface/
        └── checkpoint_step_79999_gpu_0.pt
```

`face_attr` 必须是整个目录，不能只上传 `ji.py` 和 `model_api.py`。两个权重文件如果在云平台使用，必须保留各自的文件夹层级；权重不从 GitHub 获取。

正确路径：

```text
/project/ev_sdk/src/face_attr/analyzer.py
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

错误路径示例：

```text
/project/ev_sdk/ev_sdk/src/ji.py
/project/ev_sdk/src/src/face_attr/analyzer.py
/project/ev_sdk/model/models/facexformer/model.pt
```

### 3. SDK 结构检查命令

上传后，在平台终端执行：

```bash
find /project/ev_sdk -maxdepth 6 -type f | sort
```

至少应当看到：

```text
/project/ev_sdk/src/ji.py
/project/ev_sdk/src/model_api.py
/project/ev_sdk/src/face_attr/analyzer.py
/project/ev_sdk/src/face_attr/models/facexformer/network/models/facexformer.py
/project/ev_sdk/src/face_attr/models/swinface/model.py
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

## 三、训练目录检查命令

训练文件上传后执行：

```bash
find /project/train -maxdepth 3 -type f | sort
```

训练代码至少应当包含：

```text
/project/train/src_repo/dataset.py
/project/train/src_repo/model.py
/project/train/src_repo/run.sh
/project/train/src_repo/train.py
```

检查缓存和 Git 目录：

```bash
find /project/train /project/ev_sdk \
  \( -name '__pycache__' -o -name '.git' \) -print
```

如果有输出，说明上传了缓存或 Git 元数据。它们通常不是运行必需文件，可以在重新上传时排除。

## 四、重要说明

训练输出的：

```text
/project/train/models/best_model.pth
```

与模型榜 SDK 当前使用的：

```text
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

不是同一个模型。当前 SDK 代码默认使用 FaceXFormer 和 SwinFace 两个预训练权重，并不会自动加载训练生成的 `best_model.pth`。

因此：

- 只训练：上传 `/project/train/src_repo/` 的 4 个文件。
- 做模型榜测试：再单独上传 `/project/ev_sdk/` 的源码和两个权重。
- 不要删除 `/project/train/models/` 中的平台训练输出，除非确认对应训练任务已经不再需要。
