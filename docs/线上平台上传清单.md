### 实际行为

- **每帧仍调用头肩检测器**，输出本帧person/head框、ID及原JSON字段；不复制上一帧的框或整个结果。
- 在前一帧目标与当前目标的框一对一匹配无歧义、IoU至少0.9、当前框与最近真实属性推理时的框IoU也至少0.9时，再比较头肩图像内容。
- 图像签名为32×32 BGR网格，每格采样四点取平均。整体及上方区域平均像素差均不超过3（0–255量纲），上方区域差值90分位不超过10；低纹理裁剪不复用。对照的是**最近真正运行属性模型时**的图像，避免逐帧缓慢变化无限沿用旧结果。
- 条件全部满足时，复用该目标上次的朝向和属性；最多连续复用**两帧**，第三次必须重新执行属性推理。默认batch仍为4，SwinFace仍仅处理本次需重新推理且预测front的目标。
- 目标消失、匹配歧义、明显位移/内容变化、未知朝向、画面尺寸变化或整体画面变化会重新推理；缓存只保留上一帧的目标，不长期累积人员。
- 如果调用方明确提供args字典/JSON中的sequence_id或kwargs中的sequence_id，切换该值会清空缓存；平台没有公开确认会传此字段，**不能把这一接口当作已收到文件夹边界**。无此字段时依赖图像和位置检查。内部缓存不用检测器每帧编号作为身份键，输出ID方式保持原样。

这是有期限的启发式复用，不是身份识别保证。像素相似不能证明两次输入一定是同一个人，也不能确保捕获所有细微表情、配饰或朝向变化；最多两帧可能沿用旧预测。官方第6.1节没有保证连续帧调用顺序或公开序列边界，仍需平台测试验证精度和实际命中率。若命中少，速度收益可能很小，签名检查本身也有开销；本版不保证达到30FPS或提高总分。

```text

  V5: XML 43325 个，目标 104262 个 | toward 缺失=0/front=80000/back=12000/other=12262 | gender 缺失=0/0=52131/1=52131 | race 缺失=0/0=.../1=.../2=.../3=...

  V7: ...

  抽样后各来源: V5 33334 个，V6 33333 个，V7 33333 个
```

需要核对三件事：

1. **来源组数等于实际勾选的数据集数**。如果只显示 1 组，说明多份数据落在同一目录层级，分层会退化为整体随机抽样（不会报错，但要知道）。
2. **抽样后每一份都有样本**。脚本按来源等量抽样，不会让样本数少的那份被淹没；某份样本不足配额时，剩余名额会补给还有富余的那份。
3. **各份的属性分布口径一致**。若某一份的 `gender 0=`/`1=` 比例与其他份明显相反，或 `race` 只出现部分类别，说明标签定义不同，**不要合并训练**，否则模型会学到自相矛盾的标签。

### 12 小时上限与 `MAX_SAMPLES` 的定法

平台单次训练最长 12 小时，超时会直接杀掉任务。已知坑：

- 两个脚本**串行**执行且 `run.sh` 有 `set -e`，所以前一个没跑完，后一个根本不会开始。给 SwinFace 也要留时间。
- 之前有一次 12 小时超时，是因为同时勾选了三份数据集（`有效目标 312787`、训练样本 250230），单 epoch 约 3.8 小时，5 个 epoch 要 19 小时，第 4 个 epoch 就被砍掉了。
- 两个脚本现在**每个 epoch 结束都保存一次**权重。这样即使被超时杀掉，已完成的 epoch 也不会丢；但仍然**不能**指望靠它跑完 5 个 epoch。`run.sh` 原来是循环结束后才存一次，被砍掉就是零产物。

定 `MAX_SAMPLES` 的方法：在平台终端跑一次单 epoch 并计时，算出每秒能处理的样本数，再让 `MAX_SAMPLES × 0.8 × EPOCHS ÷ 每秒样本数` 落在 12 小时以内并留出余量。

参考量级（单卡、FaceXFormer 224 输入、batch 16）：约 **0.055 秒/样本**。按此估算 `MAX_SAMPLES=100000` 时，FaceXFormer 训练 8 万样本 × 5 epoch ≈ 6.1 小时，SwinFace 输入 112 更省、约 2 小时，合计约 8 小时。

这个数字来自「日志显示跑完了 3 个 epoch」的反推，不要用小数据集外推——固定开销（模型加载、图片索引、预热）会被误当成每样本开销，导致严重高估。

新版 FaceXFormer 微调权重内含 `gender_classes=["female", "male"]`，新版 SDK 自动读取该顺序。缺少元数据的本项目旧微调产物 `facexformer_finetuned.pt` 自动按 0=女/1=男解码；其他文件名的无元数据权重默认按原始 0=男/1=女解码。旧微调权重若已重命名为 `model.pt`，需保留类别元数据或显式设置 `FACEXFORMER_GENDER_ORDER=female,male`；环境变量会覆盖权重元数据，换回原始权重时移除。

当前模型职责为：

- FaceXFormer：朝向、性别、种族；
- SwinFace：年龄、表情、眼镜、帽子、胡须；
- 年龄最终以 SwinFace 的连续回归结果为准；
- `emotion=-1` 不参与 SwinFace 表情损失。

SDK 测试至少应保留以下文件：

```text

/project/ev_sdk/src/model_api.py
/project/ev_sdk/src/face_attr/
/project/ev_sdk/model/facexformer/model.pt
/project/ev_sdk/model/swinface/checkpoint_step_79999_gpu_0.pt
```

平台终端可用以下命令检查目录：

```bash

find /project/ev_sdk/model /project/ev_sdk/src -type f | sort
```

不要上传 `__pycache__/`、`*.pyc`、`.git/` 和本地 `data/`。模型权重不提交到 GitHub，但必须保留在云平台的 SDK 目录中供训练和测试使用。

## 六、没有平台可视化结果时检查检测框

将 `project/ev_sdk/src/check_detection_boxes.py` 上传到平台 `/project/ev_sdk/src/`。该脚本使用与当前 `ji.py` 相同配置的 MTCNN，只检查检测框，不加载 FaceXFormer/SwinFace 属性权重，也不启动训练。需要 `facenet-pytorch`、PyTorch、NumPy 和 Pillow，以及可访问的图片和 VOC XML 标注。

```bash
python /project/ev_sdk/src/check_detection_boxes.py \
  --data-dir /home/data \
  --max-images 12 \
  --output-dir /project/train/result-graphs/detection_check
```

如果开发环境的 `/home/data` 中没有图片或 XML，可将已有的少量图片及对应标注放到一个目录，使用 `--data-dir` 指向该目录。只有图片而没有标注时，不能计算检测框 IoU。脚本按固定种子随机抽样，不保证小样本覆盖全部朝向；可换 `--seed` 或增加 `--max-images` 查看更多样本。

输出目录包含叠加图和 `summary.json`：绿色框是 XML 中的 `head` 标注，红色框是当前检测器预测；每个绿色框标有朝向及其与所有预测框的最大 IoU。关注预测框是否只覆盖脸部、标注框是否覆盖更大范围，以及是否没有检测到背面或侧面目标。

`GT with IoU>=0.5 candidate` 仅统计存在候选匹配框的标注数量，每个标注独立取最大 IoU，不进行一对一匹配或多边形评分，不等于平台分数。训练图片上的对照只能帮助发现框范围问题，不能直接证明隐藏测试集的漏检率；需要查看实际输出后再决定是否更换检测器。

### 单张清晰正面照片的检测对照

1. 上传新版 `check_detection_boxes.py`，替换平台 `/project/ev_sdk/src/check_detection_boxes.py`。使用 `python /project/ev_sdk/src/check_detection_boxes.py --help` 确认帮助中包含 `--image`。
2. 准备一张未打码、光线正常、眼鼻嘴可见、脸部较大的正面照片。通过平台文件上传功能将其放到 `/project/ev_sdk/src/`，文件名设为 `front_test.jpg`。不需要 XML 标注。
3. 在平台终端执行 `ls -lh /project/ev_sdk/src/front_test.jpg`，确认图片已上传到正确位置。
4. 运行下面的单图检测命令。这不启动训练，不加载 FaceXFormer/SwinFace 权重，MTCNN 参数与 SDK 一致：

```bash
python /project/ev_sdk/src/check_detection_boxes.py \
  --image /project/ev_sdk/src/front_test.jpg \
  --output-dir /project/train/result-graphs/face_control
```

5. 记录终端中的 `DEVICE=...` 和 `PRED=...`。输出目录包含 `control_front_test.jpg`（红框为预测）和 `control_report.json`；是否检测到以 `PRED` 计数和报告为准，平台预览显示时的打码不能代替检测结果。
6. 若 `PRED>=1`，打开图确认红框确实框住脸，说明检测器在这张清晰正面图上能工作；结合此前监控样本的零检测，再检查场景适配和标注范围。此结果不证明检测器对全部目标都能工作。若仍为 `PRED=0`，换另一张符合条件的照片复测，或执行下方 CPU 命令辅助排查运行环境差异，暂不直接启动大规模重训。

```bash
python /project/ev_sdk/src/check_detection_boxes.py \
  --image /project/ev_sdk/src/front_test.jpg \
  --device cpu \
  --output-dir /project/train/result-graphs/face_control_cpu
```

将两次命令输出、对应 `control_report.json` 和对照图保留用于排查。CPU 对照使用单独的输出目录，不会覆盖默认设备的结果。单图模式没有标注，不计算 IoU，也不是榜单评估。
